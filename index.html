Case study

The Watcher: a dashboard that watches on a parent's behalf, and knows when to step in itself.

Most parental-control apps stop at reporting — they tell you what happened after it already did. The Watcher was built to close that gap: it reads a child's browsing, screen time and chats in real time, scores what it finds, and lets an on-device agent take the first action — locking a screen, blocking a source, extending a limit — while the parent is still being notified.

Parent-facing app

Flutter

One codebase for the dashboard, alerts, child profiles and settings, shipped to iOS and Android from the same UI layer.

Device layer

Kotlin

Native Android integration for usage-stats access, app blocking and screen-lock — the permissions Flutter can't reach alone.

Backend

Django

Auth, child profiles, activity ingestion, and the classification logic that turns raw activity into a risk level.

What it actually does

Four things a parent opens the app to find out

Browsing

Site-by-site time and category, with a one-tap block

Every site a child visits is logged with time spent and an auto-assigned category — Gaming, Educational, Violence — so a parent can block youtube.com after an hour of flagged content without digging through history first.

Chats

Every conversation scored, not just read High risk

The chat dashboard doesn't just count messages — it ranks each contact's most recent conversation as Safe, Moderate or High risk, so a worried parent can go straight to the one chat that needs attention.

Alerts

Toxic language, late-night use, and behaviour signals

Bullying language, app activity past bedtime, and shifts in mood or anxiety all surface as their own alert type, each with a different action attached — because "block this" and "extend this" are not the same response.

Agent

An agent that can act, not just notify Auto-decision

For clear-cut cases — bullying language, a blocked category revisited — the agent locks the screen or blocks the source itself, then tells the parent what it did. Ambiguous cases still go to the parent to decide.

Screens

Eight screens, one running log

From onboarding to the alert feed the agent writes to in real time.
